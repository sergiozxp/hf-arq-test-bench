# HF-ARQ Modem Smoke 0.2.0-alpha.6

Executable: `HF-ARQ-Modem-Smoke.exe`, SHA-256
`EB8936B58883A940289A8D13D3E6694F8EA273D9E87CE38AAD6F07660E3ECE5A` (also in
`SHA256SUMS.txt`). P1 continues with this executable from attempt P1-good-10KiB-17 of
Mercury; the 46 attempts before it were run with 0.2.0-alpha.5.

Maintenance release during Phase 1 (P1). The channel simulator, the client's measurement,
the success rule and the counting are the same as in 0.2.0-alpha.5; results of both
versions are judged identically and can be combined (each run records its version).

## Why

On 2026-11-13, after 3.7 hours of the Mercury campaign block (46 attempts completed),
Mercury 1.9.19 on PC A stopped with an access violation (exit code 0xC0000005) about
20 s into attempt P1-good-10KiB-17. The block stopped correctly after three attempts in
a row that pointed to the bench. PC A had lost those attempts (no modem), while PC B had
recorded them as its own attempts, so automatic resume would have restarted the two PCs
at different attempts.

## What changes

- **Start at (blocks):** 0 (default) resumes automatically, as before; a plan position
  n makes both PCs run every attempt from position n on, without skipping, so they
  restart at the same attempt. The line beside the field shows the attempt at that
  position. An attempt run again counts once in the cross-check.
- **Automatic resume** also runs again an attempt that pointed to the bench (no
  connection in Good or Moderate), as it already did for script errors and
  infrastructure or procedure faults.
