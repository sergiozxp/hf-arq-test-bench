# HF-ARQ Modem Smoke 0.2.0-alpha.8

Executable: `HF-ARQ-Modem-Smoke.exe`, SHA-256
`88A989023F54DE1A67FC568B0544E6222C5FD8999C5F6B05168913F386132B6E` (also in
`SHA256SUMS.txt`). The VARA HF licensed campaign resumes with this executable from
P1-moderate-200B-21 (plan position 81); the remaining arms run with it.

Release during Phase 1 (P1) that keeps PC A and PC B in step. The channel simulator, the
success rule (B verifies the payload's SHA-256 and A verifies B's ACK before the
deadline) and the payload are unchanged.

## Why

On 2026-11-16, during the VARA HF licensed campaign block, PC B fell one attempt behind PC A
four times, so for most of a day each PC ran a different attempt. Each time PC B was still
in an attempt that had already ended for PC A, and took PC A's next attempt as the current
one:

- after B had sent its ACK, it waited for a BUFFER 0 that VARA never reported (until the
  ACK timeout) while its modem kept listening (P1-moderate-200B-21);
- after the link was lost in the middle of a 10 KiB transfer, both PCs waited for data
  until the 60 min deadline, and PC B's modem answered PC A's next call in the same run
  (P1-moderate-10KiB-06, P1-poor-10KiB-29);
- after a call that was never answered, PC B kept listening into PC A's next attempt
  (P1-poor-200B-24).

The payload is the same in every attempt, so the transfers still succeeded, but the
simulator had used PC B's attempt for the trace, and the cross-check paired runs with the
same name that were different sessions.

## What changes (Phase 1 attempts only; the smoke tests are unchanged)

- **The attempt ends when the session ends.** When the modem reports DISCONNECTED, PC A
  stops waiting for B's ACK and PC B stops waiting for data or for the BUFFER 0 of its ACK.
  A link lost in the middle of a transfer is a failure, as before, but it no longer runs to
  the deadline. A call that the modem gives up (DISCONNECTED without CONNECTED) ends PC A's
  attempt then.
- **PC B stops listening when PC A has stopped calling.** With the simulator in Automatic
  mode on the same PC, PC B ends an attempt without connection when the simulator has heard
  PC A's call for it and PC A has then been silent for 60 s.
- **A second session in one run** is a procedure fault (the PCs were out of step); it also
  counts for the block's bench-fault guard.
- **Cross-check:** a Phase 1 pair is counted only if PC A's and PC B's runs were the same
  session (their CONNECTED within 120 s), the simulator attempt started before PC A's run
  ended, and PC B's run received no other session. Applied to all results; the Mercury
  campaign is unaffected (180 of 180 counted).
- PC B's cleanup DISCONNECT after an attempt without connection is no longer mistaken for
  an early session.
